# GPT proposed protocol: pedestrian threshold transfer

**Status:** GPT proposal, initially prepared independently on 2026-11-03, then revised through the [GPT response](discussion_with_claude.md), Claude's reply and the [resolution note](review_resolution.md). This is a peer-discussed research design, not a frozen protocol, a record of experiments, or my merge approval. **G0 remains pending.** Source identities and access limits are in [source_audit.md](source_audit.md).

## 1. Question, population and estimands

Primary question: for a frozen detector pipeline, how does pedestrian recall on a held-out condition differ from clear-day recall when the operating threshold is selected using only clear-day data?

Primary population: BDD pedestrian annotations under a frozen eligibility policy, evaluated separately in clear daytime, clear night, and sufficiently supported weather×timeofday cells. Rain/night overlap is explicit. ACDC is a separate external-transfer panel, never pooled into BDD “night.” Rider and combined-human results are secondary until annotation policy is demonstrably aligned. Size/occlusion strata are descriptive, with boundaries frozen before test inspection; box height is not metric distance.

For model/checkpoint m, condition c and threshold t, define object-weighted recall

`R_m,c(t) = E_c[TP_i(t)] / E_c[G_i]`, and `F_m,c(t) = E_c[FP_i(t)]` (FPPI),

where G is eligible pedestrian count and the image distribution includes **zero-pedestrian images**. The sample recall is total TP divided by total eligible GT, not mean per-image recall. No eligible GT means recall is undefined. FPPI remains estimable. Freeze population weighting; sequence-average recall is a separately labelled estimand.

Choose target ρ=0.90 as the primary operating aspiration, with prespecified sensitivity targets **0.80 and 0.95**. This replaces the initial GPT 0.70/0.80 sensitivity grid before any data inspection; 0.70 is no longer confirmatory. Define `t*_m = max{observed source-selection pedestrian candidate scores t : Rhat_m,S(t) ≥ ρ}` using `score ≥ t` and whole tied groups. This finite, observed-score convention is essential to §5. An empirical attainment claim is not a population recall guarantee. Add a source-selection F1-optimal frozen threshold as a secondary policy comparator, using the same candidates/matching and highest observed boundary on tied F1; it does not exactly replicate AegisBench.

Report these distinct quantities, in percentage points where appropriate:

- **Transferred recall:** `R_m,c(t*_m)` and FPPI at exactly the same pipeline and threshold.
- **Transfer loss:** `L_m,c = R_m,clear-test(t*_m) − R_m,c(t*_m)`. This uses an independent clear test reference, not the selection recall forced toward ρ.
- **Target shortfall:** `S_m,c = max(0, ρ − R_m,c(t*_m))`; also report signed `ρ − R` so overachievement remains visible.
- **Candidate ceiling:** recall with every candidate retained under the frozen candidate policy. This is a pipeline ceiling, not detector capacity or Bayes recall.
- **Threshold-removable misses:** candidate-ceiling recall minus transferred recall on the same test slice. This is a diagnostic upper bound on recall recoverable by lowering a threshold, with no implied acceptable FP cost.

Write the frozen pipeline ceiling as `M_c` and operating recall as `r_c`, with `0 ≤ r_c ≤ M_c`. Decompose **nonnegative target shortfall** as `S_c = U_c + V_c`, where `U_c = max(0, ρ − M_c)` and `V_c = max(0, min(ρ, M_c) − r_c)`. The signed gap is separately `D_c = ρ − r_c = U_c + T_c`, where `T_c = min(ρ, M_c) − r_c` can be negative. These decompose target gaps, not the held-out clear-to-condition loss L. “Unrecoverable” means unrecoverable by lowering the final threshold within this pipeline; it does not imply physical impossibility. Undefined recall propagates to these quantities.

Pairwise detector contrasts use the same images and report both absolute target recall and differences in L. Different source baselines can produce misleading loss rankings. If source ρ is unattainable, emit **INFEASIBLE** and the ceiling, without substituting an arbitrary threshold or deleting the model. An all-candidate fallback may be reported separately. Test-slice infeasibility is a result, not grounds to change ρ. Shared lower-target comparisons must be preregistered or explicitly exploratory.

**Claude extension, accepted as an algebraic diagnostic:** let `M_c` be candidate-ceiling recall and `W_c = M_c − R_c(t*)` be threshold-removable misses in recall units. The held-out loss decomposes exactly as `L_c = (M_clear − M_c) + (W_c − W_clear)`. Both components are signed; this is a descriptive identity, not a causal attribution or a guarantee that the recoverable misses have an acceptable FPPI cost. It complements the target-gap decompositions rather than replacing them.

Empirical infeasibility means `M_S < ρ`, with no eligible source GT instead **UNDEFINED**. Define headroom `H_S = M_S − ρ`; `0 ≤ H_S < 0.02` is **LOW_HEADROOM**, not infeasibility, and does not exclude that model-target pair. The 0.02 descriptive flag is a proposal frozen before comparisons. Report uncertainty and bootstrap feasibility frequency; neither empirical attainment nor a headroom flag establishes a population guarantee.

## 2. Data separation and policy alignment

Partition by the largest available independent recording/trip/scene group before fitting anything:

| Partition | Permitted use |
|---|---|
| Source training | Fit detector weights; no evaluation reuse |
| Source development | Recipe/checkpoint selection, model debugging, policy development |
| Source calibration | Fit a prespecified score calibrator and its hyperparameters |
| Source threshold selection | Choose t* and assess empirical feasibility |
| Clear held-out test + shifted held-out tests | One frozen evaluation; no selection |
| Optional target calibration + target threshold selection | Separate adaptation arm; test groups remain disjoint |

Source is **daytime AND clear**. Other weather definitions are sensitivities, never silently mixed into “clear.” The actual group IDs and allocations require accessible labels and counts. If only validation labels are public, reserve partitions from them; do not assume official test-label access. Thin slices may make five-way source splitting wasteful: grouped cross-fitting is an alternative only with an explicit fold-specific training/selection algorithm, not pooling predictions from models that saw their test labels.

Audit class ontology, extent, ignore/crowd rules, truncation, occlusion, minimum size, category aliases and label versions in an annotation manifest. **Primary task: BDD-fine-tuned pedestrian detection**, with native rider as a separate supervised class, outside the primary recall denominator. A pedestrian-labelled detection on an eligible rider is a pedestrian-class FP; a correctly rider-labelled output is not a pedestrian prediction. This preserves the BDD task. **Separate exploratory task: COCO-pretrained zero-shot human detection**, using pedestrian ∪ rider GT, one human match per instance, excluding bicycle/motorcycle boxes. The merged-human ACDC external panel requires human-capable outputs (zero-shot person or explicitly merged pedestrian/rider outputs of a suitable fine-tuned detector); a pedestrian-only output must not be evaluated as though trained for the union. Give each panel its own source threshold and denominator. BDD `other person` and crowd handling remain proposed ignore policies pending artifact inspection; the config's `ignored_mapping` is evidence, not a substitute for reading evaluator behavior. Do not equate a cyclist-plus-bike box to a rider-only box.

For ACDC, use the extended official COCO-format instance artifact, preferring its `bbox` if verified. Any necessary derivation uses individual instance IDs/polygons, never semantic connected components. Audit extents and a stratified sample including tiny, occluded and uncertain people. Distinguish residual unlabeled/void pixels, crowd/group regions, and the **invalid mask**, which can mark legitimately labelled regions; invalid does not automatically mean ignore. Keep the proposed ignore overlap in §3 provisional until artifact and evaluator inspection. The initial adaptation proposal used ACDC train for disjoint calibrator-fit and threshold-selection groups, with val reserved for evaluation. **That allocation is on hold:** Claude's 2026-11-06 artifact inspection found shared sequence tokens across official train/val; the GPT coordinator (separate from the BDD acquisition subagent) independently confirmed that 100 fog, 56 night, 80 rain and 92 snow val frames share a token with train; [its evidence](../datasets/acdc_split_overlap_check.json) records the input hashes and method. Official split names therefore do not establish sequence disjointness. Before fitting an adaptation arm, document a grouping policy that blocks known sequence/chapter and normal/adverse dependencies, justify its independence limits, and approve a new group-disjoint allocation without using detector test results. Until then, keep unknown canonical groups null and reject held-out independence claims. No target labels enter the source-only arm. This finding does not turn source-only descriptive results into independent-group estimates.

The BDD-fine-tuned pedestrian model also has a separate ACDC `person` external panel, using its frozen BDD pedestrian threshold and explicitly documenting BDD/Cityscapes ontology and extent differences. This is distinct from the merged-human panel. Add a pedestrian/rider confusion diagnostic: among missed eligible pedestrian GT, report the fraction with a rider-labelled candidate at the frozen operating point that would meet the same geometric matching rule; match once per GT and retain the original primary error counts. Where annotations permit, stratify labelled ACDC people by invalid-pixel overlap under boundaries fixed on development data. Residual missing labels and privileged-reference labels can bias the evaluated population differently; no bias direction is assumed.

The external anchor contrast uses only adverse val views whose normal reference is also annotated, with the same correspondence eligibility and declared route/condition weights in both arms. Correspondence is at scene/view level, not pedestrian identity. Retain the larger adverse-only panel separately; do not subtract recall on all adverse images from recall on the smaller labelled reference subset and call it a matched contrast. Reference-to-adverse differences remain descriptive acquisition/scene/condition associations. Keep related normal/adverse recordings in one group across all partitions. Record image, eligible-object, empty-image, ignored-object and independent-group counts per panel and stratum. Usable project counts remain unknown; see the [source addendum](source_audit.md#peer-review-source-addendum-2026-11-03).

## 3. Freeze candidate selection and matching

Treat the unit of comparison as **weights + preprocessing + candidate selection + threshold + evaluator**. Record resize/letterbox, original-coordinate boxes, precision, foreground/background convention, class mapping, candidate floor, query count, NMS IoU, class-aware/agnostic behavior, multilabel expansion, top-k ordering, maximum detections and tie ordering. Save stable image/query/box IDs, original scores and sufficient class-score vectors; COCO scalar results alone cannot reproduce full OCE.

Primary deployment panel retains each model's declared inference semantics, with an explicitly permissive candidate floor and frozen caps. Cache candidates before the swept final threshold. For YOLO, use fixed class-aware hard NMS (proposed IoU 0.70) before sweeping; for one-to-one models use the specified branch and selection rule. Do not add NMS to DETRs merely to make box counts equal. Record class filtering **before or after** top-k: pedestrian filtering before a global cap changes the system.

Inspect raw outputs only on development or calibrator-fit groups to set floors/caps and check censoring, never on held-out test groups. Freeze a separate cap/floor sensitivity panel before final evaluation. Publish the ceiling's dependence on these choices. A shared maxDet number alone does not equalize query-class top-k and dense-box selection. Time-limited NMS must not silently truncate the record. The pinned [Ultralytics selection code](https://github.com/ultralytics/ultralytics/blob/73c60b7edf7b02b90c07157c87d05957fbfdd68f/ultralytics/utils/nms.py) and [RT-DETR top-k](https://github.com/lyuwenyu/RT-DETR/blob/df2a96c8c3a098567a1149bf0248da6efe6d495d/rtdetrv2_pytorch/src/zoo/rtdetr/rtdetr_postprocessor.py) show why these settings matter.

Primary operating-point matching: per image/class, sort descending by score with stable candidate-ID ties; greedily match each retained prediction to the highest-IoU unmatched eligible GT with IoU **≥0.50**, deterministic GT-ID ties. One prediction matches at most one GT and vice versa. Remaining duplicates are FPs. Match eligible GT before applying the documented ignore rule to unmatched predictions (proposed ignore overlap: intersection/prediction area ≥0.50); excluded GT are not FNs. Report IoU 0.75 sensitivity and ordinary AP separately, retaining the official evaluator's matching/ignore settings for AP. Recall is nondecreasing over the cached score prefixes under this primary matching rule. A maximum-cardinality matching is a labelled sensitivity, not a silent evaluator substitution.

## 4. Calibration has a different target from recall

Use two diagnostic populations: permissive cached candidates, and the actual operating subset. Detection ECE uses the binary TP label under §3, with fixed 15 equal-width bins and 10/30-bin sensitivities; report bin counts, empty bins and retained counts. A no-detection set has undefined prediction-conditioned ECE, never perfect calibration by convention. D-ECE/LaECE cannot account for every missing object simply by averaging emitted predictions.

Reproduce the exact published LaECE₀ matching and IoU target separately from IoU≥0.50 binary correctness; do not interchange those names. For OCE, preserve full class scores and its per-object aggregation; report IoU 0.50 and 0.75 components and a declared arithmetic mean. The [pinned implementation](https://github.com/azizanlab/uq-detr/blob/fa2a64fad0e6a3dfbc10c3937bd298aeeac24a9e/src/uq_detr/metrics/oce.py) exposes a scalar-score approximation; never mix it with full-score OCE across families. Include empty-scene FPPI because unrelated FPs are outside OCE's object neighborhoods. Treat OCE as a combined score/coverage diagnostic, not an independent pure-calibration predictor of recall loss.

Use binary-positive-slope Platt or positive-temperature scalar sigmoid scaling for the invariance control. Fit against a named correctness or localization target on source calibration only. A loss trained using quality targets does not prove its score is a probability of binary IoU≥0.50 correctness. Keep identity, monotone calibration, tie-producing isotonic, and any context-aware/rank-changing method as distinct arms.

## 5. Monotone recalibration: theorem and exceptions

**GPT derivation.** Let C(x) be fixed labelled boxes with scalar scores s. Let g be the same strictly increasing function for every candidate, image and condition. Suppose all upstream selection/matching is fixed or rank-equivariant, ties use identical IDs, and threshold search enumerates observed source score boundaries using the same inclusion rule. Then recall-based reselection yields `t'* = g(t*)` and, on **every** source or target image,

`{d in C(x): g(s_d) ≥ g(t*)} = {d in C(x): s_d ≥ t*}`.

**Proof:** strict increase preserves every comparison, equality group and source threshold ordering. Each observed threshold corresponds bijectively to its transformed threshold and yields the same source TP/FP set. Hence the highest feasible observed source boundary corresponds under g. The displayed equivalence holds for all real scores, including target scores absent from source. Recall and FPPI are identical. Probability-sensitive calibration metrics can change. A strictly increasing map followed by this reselection cannot rescue threshold-transfer recall. This is an algebraic control, not a hypothesis to train models to test.

The assumptions delimit important counterexamples:

| Change | Concrete consequence |
|---|---|
| Existing ties | Scores 0.8, 0.8 remain tied under strict g. Whole-group thresholding is invariant, but a target requiring half that group may have unattainable exact recall. “≥ρ” permits overshoot. Changing tie IDs or splitting ties by score-dependent randomness changes the policy. |
| Non-strict isotonic map or rounded scores | Source TP A=0.8 and FP B=0.4 both map to 0.5. A alone can no longer be selected by a scalar threshold. Even monotone nondecreasing maps can change FPPI and feasible subsets. Floating-point saturation/clipping can create the same issue. |
| Different interpolation between source scores | Source has two GT, TP scores 0.8 and 0.4, target recall 0.5. Any t in (0.4,0.8] selects the same source subset. Raw midpoint t=0.6 admits a target score 0.62. With g(s)=s², midpoint reselection gives t'=0.4 between 0.16 and 0.64; 0.62²=0.3844 is rejected. **Strict global monotonicity alone is insufficient** unless boundary selection is equivariant. The proposed observed-score rule avoids this. |
| Classwise maps plus a pooled threshold | Source has one pedestrian TP at 0.8 and one rider TP at 0.7, pooled ρ=0.5. Raw selection retains pedestrian. Map pedestrian s/2 and rider s; reselection retains rider. Both maps are strictly increasing, but cross-class ordering changes. Independent per-class thresholds remain invariant within each fixed class. |
| Nonmonotone mapping | Source TP at 0.8, FP at 0.4; g(s)=1−s puts FP above TP. A threshold satisfying full recall now includes both. Unconstrained negative-slope Platt is not the positive-slope control. |
| Multiclass logit transformation | Softmax temperature scaling is not generally g(max score): vectors (0.6,0.2,0.2) and approximately (0.55,0.45,0) reverse their max-score order at T=2. Different class maps may also change argmax labels. |
| Pipeline changes | Rerunning a fixed numerical prefilter after g(s)=s² can discard a score 0.6 at floor 0.5; it originally survived. Changing NMS, soft-NMS scores, box fusion, top-k, class labels or precision can alter candidates. Pure rank-based hard NMS with fixed boxes/ties is itself invariant under a global strict map; do not attribute changes to NMS without identifying the violated assumption. |

The same strict scalar map also preserves score-ranked top-k and greedy hard NMS **when applied before those operations**, provided boxes, labels, IoU rule, stable ties and transformed cutoffs are fixed. For hard NMS this follows inductively: each highest remaining candidate and its geometric suppression set stay the same. Moving calibration upstream alone is not an exception. Classwise maps before a cross-class selector can be an exception because they change relative ranks.

Retaining a fixed numeric threshold after calibration can change detections, but answers a different deployment-policy question. Recalibrating and selecting thresholds with **new target labels** changes the information available; a simple target-selected raw-score threshold is the necessary baseline. Neither calibration nor threshold adjustment can recover absent candidates. Conformal recall claims require a specified loss, exchangeability unit and risk statement; arbitrary weather shift does not inherit a source-only guarantee.

RQ3 keeps the strict-map invariance control and a separately labelled **fixed-probability consumer** arm (proposed cutoff 0.50, fixed in advance). Class/context-specific maps are optional rank-changing or adaptation arms with an identity-map threshold baseline; a runtime condition detector supplies context, not labels to fit a calibrator. Isotonic plateaus can merge distinct source score groups and remove attainable subsets, beyond resolving pre-existing ties. No RQ3 recall improvement is claimed in advance.

## 6. Uncertainty, dependence and interpretation

Precision pilots and allocation decisions use development or calibrator-fit groups only, never held-out test groups. Before claiming nominal confidence-interval coverage, validate the proposed bootstrap in simulations with scene clustering, discrete score boundaries, ties and near-infeasible targets. The algebraic checks already performed do not validate bootstrap coverage. Record the next-lower distinct source score and resulting boundary gap as a selector diagnostic; a large gap can affect off-source selections even under an equivariant rule.

Use a paired **group bootstrap**, proposed 2,000 replicates, sampling independent groups within each partition and any disjoint design strata. Draw each group's bootstrap weight once and reuse it across all models and every condition/slice containing that group. Keep normal/adverse counterparts together. If several trips share a known route/capture dependency, use the larger block or sensitivity analysis. If grouping metadata are unavailable, report that limitation; image bootstrap is not automatically valid. Sparse independent groups cannot support precise intervals regardless of object count. Choose a desired precision before final allocation (proposed primary-recall interval half-width: five percentage points); assess it from group-level pilot variation rather than an arbitrary object-count cutoff. Unsupported slices remain descriptive.

Report two uncertainty targets: (a) conditional on deployed t*, resample test groups only; (b) for the source-selection procedure, resample source calibration groups, refit g, resample source threshold groups, reselect t*, then resample test groups. Preserve disjointness and pairing at every stage. Repeat the declared fold-specific procedure if cross-fitting; recompute RQ2 summary statistics in their respective resampled partitions. Report threshold distributions on the native score scale, feasibility frequency, tie-group sizes and resulting metric intervals. Infeasible replicates remain a reported probability; feasible-only intervals are explicitly conditional. If a point estimate is infeasible, no ordinary transfer CI is available for that policy. These intervals condition on trained weights; training-seed variance requires actual independent training runs.

Model×condition×seed cells are dependent measurements, not independent sample size. Primary reporting is paired model-specific estimates and contrasts with intervals. Prespecify primary night/clear and model contrasts; use simultaneous bootstrap intervals if making multiple confirmatory claims. **RQ2a source-only prediction** prespecifies raw TP-ECE (15 equal-width bins, §3 matching, at source-selected t*) on source-calibration groups before fitting any map. It forecasts a model's vulnerability only for a named contrast; it cannot infer which unknown condition will occur. Fitted-map ECE must be measured on independent source groups or grouped cross-fitted predictions. **RQ2a-U unlabelled-target extension** prespecifies `A_c = mean_i max_d s_id` over permissive candidates for the panel's task (pedestrian primary, human union in its separate panel; empty image maximum = 0), with warning statistic `A_source − A_c` and source baseline from source-calibration groups. It is scene/prevalence sensitive and cannot count unseen people; it is not an identified estimator of target recall. Compare against the source-only baseline; do not tune the statistic with target labels. ATC is adjacent classification work, not a validated detector-recall estimator; see the [source addendum](source_audit.md#peer-review-source-addendum-2026-11-03).

**RQ2b target-labelled diagnostics** includes ECE/LaECE₀/OCE/AP and target oracle boundaries. These never support an advance-warning claim. Target labels are revealed only to score locked predictions/diagnostics. OCE's missed-object penalty mechanically shares information with recall. All associations remain descriptive with the initial few checkpoints. With enough diversity, validation must hold out entire models and conditions, not cells or bootstrap replicas; condition effects and seed dependence remain explicit. A mixed model does not manufacture independent architectures, and model-label permutations require justified exchangeability. Additional seeds for at least two systems improve repeatability but do not identify a general architecture effect.

Comparisons estimate differences between complete trained systems. YOLO11/YOLO26/RT-DETR differ in pretraining, backbone, size, assignment, augmentation and optimization. Matching input size, source recall or AP does not identify the causal effect of NMS removal, transformers or quality-aware loss; selecting models by test AP also leaks information. A within-backbone D-FINE versus DEIM ablation can narrow a mechanism question, with controlled recipe changes, repeated seeds and bounded scope. BDD conditions also differ in scene mix; ACDC adds dataset shift. Use “associated with condition” and “system comparison.” Box recall is not collision avoidance or planner safety.

Prioritize a **same-checkpoint YOLO26 O2O versus O2M+NMS head/pipeline contrast**, conditional on both learned branches existing and working in the pinned artifact. It reduces shared-backbone/data/recipe confounding but jointly changes head weights, assignment history, candidate counts and postprocessing. It isolates neither NMS nor assignment. Inspect checkpoint keys before branch-pruning/fusion, use separately reloaded copies, and record effective head, `nms`/`end2end`, candidate floor/cap and resolved predict/val settings. Current documentation and the official report disagree about the default; no implicit defaults are acceptable. Branch availability and runtime behavior remain unverified. If unavailable, report the missing contrast rather than substituting separately trained checkpoints as a same-checkpoint control.

**Claude source observation:** the pinned `Detect` implementation supplies detached features to the one-to-one branch. If the evaluated artifact was trained through that path, the one-to-many detection objective supplies trunk gradients while the one-to-one head learns on detached features. State this asymmetry when interpreting the contrast; code inspection alone does not establish the released checkpoint's training provenance.
